## 三、完整分层修正(full = `pms/diag.py` DiagHMR,继承 `exp_sweep/hmr2.py` Supervisor2)的实际逻辑

你的描述"规则先调执行参考,局部调整无法改善或规则处理不了时才请大模型重规划"**大体对,三处要改**:

- **L0**:执行一致性报警(跟踪 / 力误差 / 接触保护)→ 恢复后原样重跑该阶段,最多 1 次,不调大模型。
- **L1 规则**:一一对应的连续量(target / lower / upper / range / contact_at),逐分量割线法调执行侧补偿 `comp`,契约目标冻结;阶段内最快每 2 s 一次(settle 0.5 + 窗口 1.5),最多 6 次;阶段间兜底最多 2 次。
- **阶段内升级**:补偿后整体残差改善不到 10% 持续 1.5 s(平台),或变差超 10% 持续 0.5 s(撤回补偿),或 6 次用满 → 先诊断:**策略项(大模型写的 `_` 辅助项)压着 → 直接 L2**;否则(固定约束压着 / 无约束压着)先做一次求解器补救(采样噪声 ×3,持续 2 s,每阶段一次),仍不降再 L2。
- **阶段末**:策略项压着 → 直接 L2;规则判补偿无效的连续量 → 下一趟全程噪声 ×3 重跑一次;**只剩连续量不过且有约束压着 → 跳过 L1b 直接 L2**;其余(一对多等规则管不了的项)→ **L1b:大模型只算补偿量**(只改 comp,不重写策略),最多 3 轮;L1b 给不出补丁或判不可达 → L2。
- **L2**:大模型重写这一阶段的策略项与全部 comp(契约锁定),每阶段 1 次;总尝试数有上限,用满即中止。

要改的三处:① 规则管不了的偏差下一步是 L1b(大模型算补偿量),不是重规划;② 策略项冲突时跳过规则 / 补救直接 L2;③ 中间还有一层不调大模型的求解器补救。
另:我上一版说的 L2 条件"补偿后改善不到 20%""改好一项坏一项"是基类 `supervise.py` 的规则,full 走的 Supervisor2 重写了阶段末门控,这两条**不生效**;实际是上面的 10% 平台 / 变差判据。flat 每阶段只调一次 L2,full 先有多轮低成本迭代,正文应说明。
